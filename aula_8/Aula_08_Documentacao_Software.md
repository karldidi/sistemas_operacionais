# Aula 08 — Documentação de Software

A aula apresentou a importância da documentação de software para explicar como um projeto funciona, como deve ser instalado, configurado, executado, testado e mantido. Foi destacado que a ausência de documentação dificulta a entrada de novos desenvolvedores, aumenta o tempo de manutenção, causa configurações inconsistentes e faz com que o conhecimento fique concentrado em poucas pessoas.

A documentação foi relacionada a diferentes áreas, como Engenharia de Software, Gestão de Projetos, DevOps, Segurança da Informação, Qualidade de Software e Produto/UX. Também foram apresentados seus principais usuários: desenvolvedores, testadores, equipes de DevOps, gestores e usuários finais.

O conteúdo diferenciou documentação técnica, que descreve arquitetura, APIs e componentes; documentação de projeto, que registra objetivos, escopo e requisitos; e documentação de processo, que explica práticas de desenvolvimento, controle de versão, testes, integração e publicação.

Um dos principais destaques foi o arquivo README, geralmente a primeira referência encontrada em um repositório GitHub. Ele deve apresentar o objetivo do projeto, as tecnologias utilizadas, os pré-requisitos, as instruções de instalação e execução, as configurações necessárias, os testes, a estrutura das pastas e orientações para contribuição.

A aula também abordou a documentação do processo DevOps, desde o desenvolvimento e uso do Git até os testes, pipelines de integração e entrega contínuas (CI/CD) e deploy. Foi reforçada a importância de não incluir informações sigilosas na documentação ou no repositório, como senhas, tokens, chaves de API e dados pessoais.

Como atividade, foi proposto escolher um projeto, descrever seus objetivos, problema, escopo, requisitos, tecnologias e arquitetura e criar ou atualizar seu README com instruções suficientes para que outra pessoa consiga compreender e executar o sistema.
